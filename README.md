# 나라장터 용역 텔레그램 알림 봇

나라장터의 **입찰공고 + 사전규격 + 발주계획** (업무구분: 용역)을 자동으로 조회해서,
아래 조건에 맞는 건만 텔레그램으로 알림을 보내주는 스크립트입니다.

| 구분 | 판별 키워드(공고명/사업명) | 알림 조건 |
|---|---|---|
| 건진법(건설기술진흥법) | 건설사업관리 / CM / 건설기술용역 | 기초금액·용역금액·예산액 중 하나라도 **10억 이상** |
| 주택법 | 주택법 / 감리 / 감리자 / 주택 | 첨부파일 본문에 **"면접"** 포함 시 알림. 첨부파일이 없거나 텍스트 추출에 실패하면 → **10억 이상** 기준으로 대체 알림 (⚠ 표시) |

키워드와 금액 기준은 `config.py`에서 자유롭게 수정할 수 있습니다.

---

## 1. 준비물

### 1) 공공데이터포털 API 인증키 (무료)
1. https://www.data.go.kr 가입 및 로그인
2. 아래 3개 서비스를 각각 검색해서 **"활용신청"** 클릭 (자동승인이라 보통 바로 사용 가능)
   - 조달청_나라장터 입찰공고정보서비스
   - 조달청_나라장터 사전규격정보서비스
   - 조달청_나라장터 발주계획현황서비스
3. 마이페이지 > 개발계정 상세에서 **일반 인증키(Decoding)** 복사

### 2) 텔레그램 봇 토큰 + chat_id
1. 텔레그램 앱에서 `@BotFather` 검색 → 대화 시작
2. `/newbot` 입력 → 이름 정하기 → 발급된 토큰(예: `123456789:ABCdef...`) 복사
3. 방금 만든 봇과 아무 메시지나 한 번 주고받기 (예: "안녕")
4. 브라우저에서 아래 주소 접속 (토큰 부분만 본인 것으로 교체)
   `https://api.telegram.org/bot<토큰>/getUpdates`
5. 응답 JSON에서 `"chat":{"id": 123456789, ...}` 부분의 숫자가 chat_id

## 2. 설치 (GitHub Actions로 24시간 자동 실행 - 추천)

컴퓨터를 켜둘 수 없는 상황이라면, **GitHub Actions**를 쓰는 게 가장 좋습니다.
비용 없이, 깃허브가 대신 10분마다 이 스크립트를 실행해줍니다.

### 1) GitHub 저장소 만들기
1. https://github.com 가입 (이미 있으면 생략)
2. 우측 상단 `+` → `New repository` 클릭
3. 저장소 이름 아무거나 입력 (예: `nara-telegram-alert`)
4. **Public**으로 설정 (Public이어야 Actions 실행이 완전 무료·무제한입니다.
   코드 안에 실제 API 키는 들어있지 않고, 아래 4번에서 별도 "Secrets"로만
   보관하니 공개해도 키가 노출되지 않습니다.)
5. `Create repository` 클릭

### 2) 이 폴더 내용을 저장소에 올리기
받으신 압축을 풀고, 그 폴더에서:
```bash
cd nara-telegram-alert
git init
git add .
git commit -m "초기 세팅"
git branch -M main
git remote add origin https://github.com/본인아이디/저장소이름.git
git push -u origin main
```
(git이 없다면 https://git-scm.com 에서 설치, 또는 GitHub 데스크톱 앱으로 드래그해서 올려도 됩니다)

### 3) API 키 / 텔레그램 정보를 "Secrets"에 등록
방금 만든 저장소 페이지에서:
`Settings` → 왼쪽 메뉴 `Secrets and variables` → `Actions` → `New repository secret`

아래 3개를 각각 등록:
| Name | Value |
|---|---|
| `NARA_SERVICE_KEY` | 공공데이터포털에서 발급받은 인증키 |
| `TELEGRAM_BOT_TOKEN` | 텔레그램 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 본인 chat_id |

이 값들은 코드에 직접 적지 않고, 이렇게 Secrets로 등록하면 실행할 때만 안전하게 주입됩니다.

### 4) 확인
저장소 페이지 상단 `Actions` 탭 → `나라장터 용역 텔레그램 알림` 워크플로우 클릭 →
`Run workflow` 버튼으로 수동 실행해서 정상 동작하는지 먼저 테스트해보세요.
문제없이 실행되면, 이후로는 컴퓨터를 꺼두셔도 10분마다 자동으로 확인하고
텔레그램으로 알림이 옵니다.


## 3. 실행 (로컬/서버 방식일 때)

GitHub Actions를 쓰신다면 이 단계는 필요 없습니다 (워크플로우가 자동으로 실행합니다).
로컬/서버에서 직접 돌리시는 경우에만:

```bash
python main.py
```

정상적으로 조건에 맞는 공고가 있으면 텔레그램으로 메시지가 도착합니다.
이미 알림을 보낸 건은 `seen_items.json`에 기록되어 다음 실행부터는 중복으로 오지 않습니다.

## 4. 자동으로 주기 실행하기 (로컬/서버 방식일 때)

GitHub Actions를 쓰신다면 스케줄은 이미 `.github/workflows/nara-alert.yml`에
"10분마다 항상 트리거"로 설정되어 있고, 실제 실행 여부는 아래 표에 따라
`scheduler.py`가 알아서 판단하므로 **이 섹션은 로컬/서버 방식에서만 참고하시면 됩니다.**

### 요일/시간대별 차등 스케줄이 적용되어 있습니다

| 시간대 | 평일 | 주말 |
|---|---|---|
| 08:00–19:59 | 10분마다 | 3시간마다 (8/11/14/17시) |
| 20:00–23:59 | 1시간마다 | 23:50 딱 한 번 |
| 00:00–07:59 | 1시간마다 (그날이 평일이면) | 실행 안 함 (그날이 주말이면) |

이렇게 복잡한 규칙은 crontab 문법만으로 표현하면 자정 경계, 평일/주말 전환에서
실수하기 쉬워서, **cron은 "10분마다 항상 실행"이라는 단순한 규칙 하나만 걸어두고,
실제로 지금이 조회할 타이밍인지는 `scheduler.py`가 판단**하도록 만들었습니다.
타이밍이 아니면 API를 전혀 호출하지 않고 바로 종료되니 안심하고 짧은 간격으로 걸어두면 됩니다.

규칙을 바꾸고 싶으면 `config.py`의 `DAY_PERIOD_START_HOUR`, `DAY_PERIOD_END_HOUR`,
`WEEKEND_DAY_ANCHOR_HOURS`, `WEEKEND_NIGHT_RUN_HOUR/MINUTE` 값만 수정하면 됩니다.

### Mac / Linux (cron)
```bash
crontab -e
```
아래 줄 추가 (항상 10분마다 실행 - 내부적으로 스케줄이 알아서 걸러냄):
```
*/10 * * * * cd /절대경로/nara-telegram-alert && /usr/bin/python3 main.py >> run.log 2>&1
```

### Windows (작업 스케줄러)
1. "작업 스케줄러" 실행 → "기본 작업 만들기"
2. 트리거: 매일 → "반복 간격" 10분으로 설정
3. 동작: 프로그램 시작 → `python.exe`, 인수에 `main.py`의 절대경로, "시작 위치"에 프로젝트 폴더 지정

### API 호출 한도 참고
공공데이터포털 개발계정은 보통 **하루 1,000회** 호출로 제한됩니다. 위 스케줄대로면
평일 낮(10분마다, 12시간) 72회 + 평일 밤(1시간마다, 12시간) 12회 = 평일 하루 약 84회 실행,
주말은 낮 4회 + 밤 1회 = 약 5회 실행 정도라 **기본 한도로도 충분히 여유 있습니다**
(실행당 API 호출 3~4회 기준으로도 하루 최대 약 340회 수준). 별도로 트래픽 증가 신청을
하지 않아도 될 가능성이 높지만, 주택법 매칭 건이 유난히 많은 날은 e발주 첨부파일 조회가
늘어날 수 있으니 `run.log`를 한 번씩 확인해보시는 걸 추천드려요.

### 24시간 켜둔 서버/클라우드에서 돌리고 싶다면
가장 간단한 방법은 저렴한 VM(오라클 클라우드 free tier, 개인 라즈베리파이 등)에 이 폴더를 올리고 위 cron 설정을 그대로 쓰는 것입니다.

## 5. 커스터마이징 포인트

- **키워드/금액 기준**: `config.py`
- **알림 메시지 양식**: `templates.py` (4개 양식: 본공고-주택법 / 본공고-CM / 발주계획 / 사전규격)
- **양식에 들어갈 값 추출 로직(정규식)**: `field_extractor.py`
- **조회 기간(며칠 전 것까지 볼지)**: `config.py`의 `LOOKBACK_DAYS`

### 메시지 양식이 실제로 어떻게 채워지는지
- 첨부파일/공고 본문 텍스트에서 정규식으로 값을 뽑아내며, **확실하지 않은 항목은 절대 추측하지 않고 "파악중"으로 표시**합니다.
- 메시지 안에 "파악중"이 하나라도 있으면 맨 아래 `* 확인이 필요합니다.` 문구가 자동으로 붙습니다.
- "발주시기"는 항상 "파악중"으로 고정됩니다 (요청사항).
- ⚠ **정규식은 일반적인 공고문 표현을 기준으로 만든 것이라, 실제 문서 표현이 다르면 값을 못 찾을 수 있습니다.** 며칠 사용해보시고 특정 항목이 자주 "파악중"으로 나온다면, `field_extractor.py`에서 해당 항목의 정규식 패턴만 다듬으면 됩니다(함수가 항목별로 독립되어 있어 하나씩 고쳐도 다른 부분에 영향 없음).

## 6. 참고 / 한계

- 발주계획현황서비스(`OrderPlanSttusService`)는 공식 문서상 응답 필드명이 다른 서비스보다 정보가 적어서, `main.py`의 `process_order_plans()`에 여러 후보 필드명을 넣어뒀습니다. 처음 실행 후 실제 응답을 한 번 콘솔에 찍어보고(`print(items[0])` 등) 필드명이 다르면 해당 부분만 맞춰주세요.
- "기초금액"은 별도 API 호출이 필요한 경우가 있어, 실무적으로 입찰공고에 함께 오는 예산금액/추정가격 중 큰 값을 기준으로 판단합니다. 정확한 기초금액이 꼭 필요하다면 입찰공고 상세조회(기초금액정보) 오퍼레이션을 추가로 붙이면 됩니다.
- HWP(구버전) 텍스트 추출은 완벽하지 않을 수 있습니다 (암호화된 파일, 이미지로만 된 스캔본 등은 추출 불가). 이 경우 "확인 실패"로 처리되어 금액 기준으로 자동 대체됩니다.
- 하루 여러 번 실행할 계획이라면 공공데이터포털의 트래픽 제한(개발계정 기본 1,000회/일)을 넘지 않는지 확인하세요.
